## 1. 接线

### 1.1 信号对应关系

| 信号 | MCU 引脚 | 板载收发器 U1 | 主板端子（XT30PW-M 2+2） | 适配器接口 |
|---|---|---|---|---|
| CAN1_TX | **PD1**（FDCAN1，AF9） | TXD ← PD1 | — | — |
| CAN1_RX | **PD0**（FDCAN1，AF9） | RXD → PD0 | — | — |
| CAN_H | 经 U1 | CANH | 第 4 脚 | CAN 座 **H** |
| CAN_L | 经 U1 | CANL | 第 3 脚 | CAN 座 **L** |
| GND | GND | — | 第 2 脚（INGND） | **UART 座第 1 脚 GND** |

> MCU 并不直接连到端子上：**PD1/PD0** 经板载收发器 U1 变成 CANH/CANL，再引到端子。
> 所以"CAN_H 接 PD1"是错的，正确说法是"CAN_H 经 U1 由 **PD1** 发送、**PD0** 接收"。

### 1.2 适配器接口（说明书第 3 页）

| 接口 | 类型 | 线序 | 本工程用法 |
|---|---|---|---|
| 电源&通信 | Type-C | — | 接 PC，供电 + 通信 |
| UART | GH1.25 3P | **GND / TX / RX** | 只用 **GND**（第 1 脚）→ 主板第 2 脚 INGND |
| CAN | GH1.25 2P | **H / L** | H → 主板第 4 脚；L → 主板第 3 脚 |
| 终端电阻 | 拨码 | ON / OFF | 保持 ON（120 Ω 已接入） |

> CAN 座只有 H、L，**没有地**；GND 必须从 UART 座的第 1 脚引到主板，否则总线没有共同参考点。

### 1.3 接线清单

| 适配器引脚 | 接到主板 |
|---|---|
| CAN 座 **H** | 端子**第 4 脚**（CAN1_H） |
| CAN 座 **L** | 端子**第 3 脚**（CAN1_L） |
| UART 座 **GND**（第 1 脚） | 端子**第 2 脚**（INGND），或任意 GND 孔 |
| UART 座 TX / RX | 悬空 |
| Type-C | PC USB（供电 + 通信） |

供电：收发器 U1 由 **VCC_5VS** 供电，主板必须插 USB-C 或接 24 V 电池；
只插 ST-Link 时总线不工作（原理图注记：使用 CAN 总线需要 USB 供电或者 24V 电源供电）。

## 2. 串口协议（CDC，官方格式）

适配器出厂固件即支持，序列口速率设为 10 Mbit/s（CDC 实际速率无关）。

**PC → 适配器（30 字节）**

| 偏移 | 内容 |
|---|---|
| 0–1 | `55 AA` |
| 2 | 帧长 `0x1E` |
| 3 | 命令：`0x01` 转发并回报状态，`0x03` 静默转发 |
| 4–7 | 发送次数 u32 |
| 8–11 | 发送间隔 u32（单位 100 µs） |
| 12 | ID 类型：0 标准帧，1 扩展帧 |
| 13–16 | CAN ID u32（小端） |
| 17 | 帧类型：0 数据帧，1 远程帧 |
| 18 | 数据长度 |
| 19–20 | idAcc / dataAcc |
| 21–28 | data[8] |
| 29 | CRC-8（初值 0，多项式 0x8C，LSB 优先） |

**适配器 → PC（16 字节）**

| 偏移 | 内容 |
|---|---|
| 0 | `AA` |
| 1 | 命令：`0x11` 接收成功，`0x12` 发送成功，`0x02` 发送失败，`0x01` 接收失败 |
| 2 | 长度(6) / ide(1) / rtr(1) |
| 3–6 | CAN ID u32（小端） |
| 7–14 | data[8] |
| 15 | `55` |

**四字节命令**

| 命令 | 含义 |
|---|---|
| `55 02 AA 55` | 握手 |
| `55 03 AA 55` | 停止连续发送 |
| `55 05 <idx> AA 55` | 设置 CAN 波特率；idx 0=1M、3=500k、5=250k、7=125k |

> 收到 `0x02 发送失败` 表示**总线上没有节点应答**：接线、共地、5 V 供电或波特率不匹配。

## 3. 帧映射

| 方向 | 11 位标识符 | 载荷 |
|---|---|---|
| MCU→PC | `0x601` | `data[0]` 段序号，`data[1..7]` 应用数据 |
| PC→MCU | `0x600` | 同上 |

应用层仍是 V1.0 协议帧（`A5 5A` 头 + CRC16），一条状态帧 45 字节，拆成 7 个 CAN 帧。

## 5. 排查表

| 现象 | 处理 |
|---|---|
| `发送失败(0x02)` | 总线上无 ACK：查 CAN_H/CAN_L 接线（端子第 4/3 脚）、共地、5 V 供电、波特率 |
| `接收失败(0x01)` | 总线错误，多为波特率不一致 |
| 能发不收 | 段序号从 0 开始，检查 MCU 端 `can_link.c` 的 0x601 发送 |
| 握手无应答 | 设备非该协议固件（如 FD 版），换 `--can` + SLCAN/gs_usb |

## 6. 本轮实测记录

- 适配器回帧验证：发送 `0x600` 帧后收到
  `AA 02 08 00 06 00 00 00 A5 5A 10 02 00 00 00 55`
  → 命令 `0x02`（无 ACK）、CAN ID 正确解析为 `0x600`，证明帧格式与 CRC 实现正确。
- 依次尝试索引 0–8（1M→100k），均无 ACK，说明 MCU 侧尚未在总线上应答，
  需先确认 CAN_H/CAN_L 接线、共地与 5 V 供电。
